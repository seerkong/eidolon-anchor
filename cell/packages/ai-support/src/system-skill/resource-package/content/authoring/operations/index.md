# Authoring operations

Compose the exact protocols needed for the current lifecycle and invoke native tools with explicit session, resource, revision, and authorization facts. A ResourcePackage update is the bounded control loop `open -> bounded inspect -> batch patch -> validate/prepare`, not a choice of only one isolated operation:

- `open-resource-package.md`: open the complete workspace ResourcePackage as the canonical App/Workflow/Agent/Material authoring unit.
- `create-resource-package.md`: call the dedicated `WorkflowCreateResourcePackageSession` tool with one model-authored complete file set when no workspace package exists.
- `inspect.md`: compact session facts plus exceptional, exact `WorkflowWorkspace` inspection operations.
- `batch-patch.md`: one expected-revision `WorkflowWorkspace(operation=patch)` for a coherent add/update/delete set.
- `validate-prepare.md`: the single canonical Halfcode/depa ResourcePackage validation and `WorkflowPreparePublication` proof, followed by a typed ready receipt. Do not use the legacy `WorkflowWorkspace(operation=validate)` for a ResourcePackage session.
- `publish.md`: `WorkflowPublishAuthoringSession` with the exact prepared revision and independent publication authorization; `WorkflowQueryResourcePackagePublication` recovers `status: "publication_outcome_unknown"` without repeating publication.
- `legacy-vfs-workflow.md`: explicit compatibility-only workflow-bundle authoring whose identity remains `vfs://`.
- `agent-definition.md`: author the complete schema, EffectPolicy, MaterialPort/Binding/value and runtime-first Ctrl/Data `runAgent` / `runTargetedAgent` task contract.
- `step-space.md`: author explicit StepSpace/Step/Group/Extension refs and schema-bound initial extension values without copying runtime sidecar storage rules.
- `ai-workflow.md`: create/edit AI Data/Ctrl definitions, load native XNL grammar, repair diagnostics and continue from authoring proof to an authorized run.

The model owns semantic Kind/profile/topology and repair choices. Query `WorkflowGetAuthoringContext` with an installed Kind name for its current schema, KindDefinition source and fingerprints; do not recreate standard definitions from memory. Native components own parser, containment, CAS, digest, build/proof, whole-package publication and registry readback algorithms. Publication authorization and execution authorization are separate; runtime facts never rewrite source.

For an existing workspace ResourcePackage, call `WorkflowOpenAuthoringSession` immediately before loading grammar references. Empty input deterministically opens that package; `artifact_kind: "resource-package"` and `source_kind: "workspace-layer"` remain the explicit equivalent. If this exact operation reports that no complete workspace package exists, load `create-resource-package.md` with the exact authoring and grammar references, then call `WorkflowCreateResourcePackageSession`; do not fall back to a legacy bundle. Do not query App, reusable-Agent, template or prebuilt lists first. Without `selected_resource_refs`, the deterministic open selects every workspace-owned App and reusable-Agent root; pass explicit refs only when a narrower exact set is already known. The receipt returns the bounded source `selection`, including canonical workspace-owned effective KindDefinition documents; when it is not truncated, do not call `describe`, `tree`, `read_selection`, App list or Agent list, and do not search or read those definitions again.
