# Coding protocol

1. For an existing workspace ResourcePackage, use the first post-stage provider completion to load `sys-eidolon-anchor-authoring` plus `operations/index.md` and query only missing exact App and reusable-Agent identities. Do not query templates or prebuilt workflows and do not read grammar references yet.
2. In the next provider completion, call `WorkflowOpenAuthoringSession` with the exact discovered `selected_resource_refs`. The same deterministic open receipt establishes durable recoverable state and returns its bounded `selection` with exact App/Workflow/Agent/Material source plus the workspace-owned effective KindDefinition documents for every resource kind in that closure. Do not follow that receipt with `describe`, `tree`, or `read_selection` when `selection.truncated` is false.
3. In the next provider completion, use the returned selection to choose and load `sys-halfcode-resource-dsl`, the exact generated workflow profile reference, and the needed batch/proof operation resources in parallel when possible. When the selection is not truncated, do not search or read those KindDefinition paths again. Opening and reading exact source do not authorize or choose semantic topology.
4. Submit the first coherent expected-revision batch patch in the following provider completion. Read a non-resource dependency only when the returned exact source names it. Use an exact `read`/`read_many`, `search`, or necessary `tree` only when the open receipt is truncated or leaves a specific exact path unresolved. If exact source already satisfies the request, transition directly to proof. Do not consume the no-progress budget with redundant workspace inspection or repeated KindDefinition loading.
5. After the ResourcePackage patch call `WorkflowPreparePublication` directly. `WorkflowWorkspace(operation=validate)` is compatibility-only for a legacy workflow bundle. Consume structured diagnostics from the single package proof authority; a diagnostic permits one focused read-and-repair cycle and does not authorize speculative extra inspection.
6. When the requested outcome includes proof, a coherent mutation must be followed in the next provider completion by `WorkflowLoadStageContext({ "stage": "testing" })`; do not finish from `coding` or claim that `WorkflowPreparePublication` is unavailable. In `testing`, call `WorkflowPreparePublication`, then `WorkflowCompleteAuthoring` with the exact ready revision. Neither step publishes or runs the workflow.

The host must not map wording, topology, profile, operation, or reference paths for the model.
