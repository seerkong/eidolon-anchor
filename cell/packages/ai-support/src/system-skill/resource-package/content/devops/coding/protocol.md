# Coding protocol

1. The coding stage context already contains the Authoring root and `operations/index.md`. Use the first post-stage provider completion to call `WorkflowOpenAuthoringSession` directly; empty input is the deterministic existing workspace-package default. Do not load those two Skill resources again and do not query App, reusable-Agent, template or prebuilt lists before opening.
2. If an existing package opens, its exact selection defaults to all workspace-owned App and reusable-Agent roots and returns bounded App/Workflow/Agent/Material source plus the workspace-owned effective KindDefinition documents for every resource kind in the closure. Supply `selected_resource_refs` only when the caller already holds a narrower exact selection. Do not follow a non-truncated receipt with `describe`, `tree`, `read_selection`, App list or Agent list.
3. If the exact open result instead says no complete workspace ResourcePackage exists, use one generic Authoring `Skill.resources` batch for `operations/create-resource-package.md`, `operations/validate-prepare.md`, `operations/agent-definition.md`, `references/flow-dsl/spec/ai-workflow/resources.md`, `references/flow-dsl/spec/ai-workflow/ctrl-workflow.md`, `references/flow-dsl/spec/ai-workflow/data-workflow.md`, `references/flow-dsl/std/ai-ctrl-workflow/axioms.md`, and `references/flow-dsl/std/ai-data-workflow/axioms.md`. In the following completion load `sys-halfcode-resource-dsl` once with `references/resource-dsl/index.md`, `references/resource-dsl/documents.md`, `references/resource-dsl/files.md`, `references/resource-dsl/examples/resource-package.xnl`, and `references/resource-dsl/examples/kind-definition.xnl`. Then call `WorkflowCreateResourcePackageSession` with one complete file set; do not create a legacy bundle or placeholder package.
4. For an existing package, submit the first coherent expected-revision batch patch after the exact reference batches. For a fresh package, the successful complete create is already the first durable source revision. Read a non-resource dependency only when returned exact source names it. Use exact inspection only when a receipt is truncated or leaves a specific exact path unresolved. If exact source already satisfies the request, transition directly to proof. Do not consume the no-progress budget with redundant Skill loads, workspace inspection or repeated KindDefinition loading.
5. After the ResourcePackage patch call `WorkflowPreparePublication` directly. `WorkflowWorkspace(operation=validate)` is compatibility-only for a legacy workflow bundle. Consume structured diagnostics from the single package proof authority; a diagnostic permits one focused read-and-repair cycle and does not authorize speculative extra inspection.
6. When the requested outcome includes proof, a coherent mutation must be followed in the next provider completion by `WorkflowLoadStageContext({ "stage": "testing" })`; do not finish from `coding` or claim that `WorkflowPreparePublication` is unavailable. In `testing`, call `WorkflowPreparePublication`, then `WorkflowCompleteAuthoring` with the exact ready revision. Neither step publishes or runs the workflow.

The host must not map wording, topology, profile, operation, or reference paths for the model.
