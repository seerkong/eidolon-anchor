# Design

## 上下文

测试必须同时满足真实 TUI 产品入口、真实公网、多个独立来源和可重复自动验收。公网内容天然变化，因此不能断言固定新闻标题。

## 方案概览

1. 使用三个不同域名的公开机器可读入口：`hn.algolia.com`、`api.github.com`、`dev.to`。
2. 第一轮自然语言完整列出三个 URL，并要求综合来源生成中文报告。
3. workflow 的 `ai.agent` effect 在 child actor 内依次发起三个标准 `bash/curl` tool call。
4. 脚本化模型 adapter 从真实 tool results 提取动态标题或项目名称，再形成报告。
5. 生命周期断言保持两段授权：发布前和执行前均不得产生任何来源证据；执行后来源集合必须精确覆盖三个域名。
6. 报告断言使用运行时提取的动态证据和来源域名，不绑定特定热点内容。

## 影响范围与修改点（Impact）

- `terminal/packages/tui/tests/workflow-human-journey-e2e.test.ts`
- 仅当测试红灯暴露生产缺陷时，才修改共享 runtime。

## 决策摘要

- 公网内容是真实事实源；脚本化 adapter 仅承担可重复的模型决策，不伪造网络响应。
- 三个来源必须是不同域名，每个来源都必须留下成功 tool result 证据。
- 公网不可达属于该真实 E2E 的明确失败，不回退到本地 fixture。

## 风险 / 权衡

- 公网服务可临时不可达或限流；测试会给出逐来源诊断，保留真实失败而不静默跳过。
- JSON 字段可能演进；提取逻辑只依赖各公开入口最基本的标题/名称字段。
